SUMMARY OF WORK COMPLETED — WEEK 2 (PHARMEAZOR)
=================================================

OBJECTIVE
---------
Build the Week 2 retrieval layer for the Pharmeazor project: chunk the
collected documents, compute embeddings, build a vector database, and
compare keyword search (BM25) with semantic search on the project questions.

1. ENVIRONMENT
--------------
- Recreated .venv with Python 3.12.16 (uv) because the original 3.14.10
  environment was incompatible with the ML stack.
- Added and pinned in requirements.txt:
  sentence-transformers==6.3.0, faiss-cpu==1.16.0, bm25s==0.3.16.
- Note: PyStemmer was tried for stemming, then removed (see section 8).

2. THESAURUS PARSER FIX
-----------------------
- Rewrote scripts/05_clean_thesaurus.py.
- Bug: the old parser treated uppercase risk labels (e.g. "ASDEC - APEC")
  as section headings, merging interaction blocks.
- Fix: heading detection by font size (HEADING_MIN_SIZE = 9.5) instead of
  uppercase; added _titre_valide, _premier_bloc, _page_lines,
  membres capture, and level normalization.
- Corrected corpus: 614 substances / 3,218 interactions
  (Week 1 report said 801 / 2,561).

3. CONFIGURATION
----------------
- src/pharmeazor/config.py: added INDEX_DIR (db/index),
  CORPUS_PATH (data/processed/week_2/corpus.jsonl), and EMBEDDING_MODEL
  (default intfloat/multilingual-e5-small, overridable by env var).

4. CORPUS AND CHUNKING
----------------------
- src/pharmeazor/corpus.py: builders for thesaurus, nomenclature, nomenclature_dz,
  EMA, DWA, pharmnet, plus write_corpus / load_corpus.
- scripts/07_build_corpus.py produces data/processed/week_2/corpus.jsonl.
- Chunk schema: chunk_id, doc_id, source_id, source_name, authority_rank,
  lang, text, metadata.
- Chunking choices:
  * Thesaurus: 1 chunk per interaction (substance + target + level +
    description + management + class members).
  * Nomenclature: aggregated to 1 chunk per DCI (was 5,425 product rows,
    now 1,387 chunks listing brands, forms, dosages, labs). This removes
    near-duplicate noise while keeping dosage/brand information.
  * Pharm'Net: aggregated to 1 chunk per DCI from produits_enregistres.csv
    (5,387 registered rows -> 1,247 chunks listing class, brands, forms,
    dosages, labs, schedule and PPA price range). Retired products excluded.
  * Algerian nomenclature (ANPP): aggregated to 1 chunk per DCI from
    algerian_drug_nomenclature.csv (4,627 product rows -> 1,299 chunks
    listing DCI code, brands, forms, dosages, labs/countries, schedule,
    registration status, reimbursement and price).
  * EMA: 1 chunk per medicine. DWA: 1 chunk per list entry.
- Total corpus: 9,546 chunks
  (Thesaurus 3,218; EMA 2,365; MIPH 1,387; ANPP 1,299; Pharm'Net 1,247; DWA 30).
- Authority ranks: thesaurus 3, ema 3, dwa 2, nomenclature 1, pharmnet 1,
  nomenclature_dz 1.

5. EMBEDDINGS AND INDEXES
-------------------------
- src/pharmeazor/embeddings.py: e5 prefix handling ("query: " / "passage: "),
  model cache, normalized vectors.
- src/pharmeazor/index.py: build_faiss (IndexFlatIP), build_bm25,
  load_faiss, load_bm25.
- scripts/08_build_index.py builds both indexes.
- FAISS: 9,546 x 384, build time ~284 s on CPU, file db/index/faiss.index
  (~14.0 MB). chunk_ids.json maps vectors to chunk IDs.
- BM25: bm25s, French stopwords, no stemming, build time ~0.6 s,
  saved under db/index/bm25/.

6. RETRIEVAL
------------
- src/pharmeazor/retrieval.py: Retriever class with:
  * search_dense  (FAISS top-k)
  * search_bm25   (lexical top-k)
  * search_hybrid (Reciprocal Rank Fusion, k=60)
  * search(query, k, method)
- Measured latency per query (CPU, after model load):
  BM25 0.37 ms; dense 18.0 ms; hybrid 18.1 ms.
  (Model load adds ~10 s per process.)

7. EVALUATION
-------------
- src/pharmeazor/evaluation.py + scripts/09_eval_retrieval.py.
- Queries: Q1 paracetamol dosage, Q2 ibuprofen + aspirin, Q3 the real
  Amlodipine + Ibuprofen mission question, Q3f a short diagnostic variant,
  Q4 source-conflict meta question, Q5 out-of-scope (dental pain).
- Manual gold chunk sets; metrics: Recall@10, Recall@50, Hit@10, MRR@100,
  nDCG@10, top-100 ranking.
- Output: data/processed/week_2/retrieval_comparison.md.

  Aggregate (real questions Q1, Q2, Q3):
  Method   Recall@10  Recall@50  Hit@10  MRR@100  nDCG@10
  BM25       0.083      0.250     0.333   0.333    0.130
  Dense      0.333      0.500     0.333   0.085    0.129
  Hybrid     0.167      0.250     0.333   0.058    0.084

  Key per-question result:
  - Q1 (dosage): dense finds the correct chunk at rank 5 (R@10 = 1.0).
    After adding the ANPP catalog, BM25 no longer reaches the gold chunk in
    the top-100 because several catalog chunks compete for "paracetamol".
  - Q2 (ibuprofen + aspirin): all methods fail at top-10 due to the synonym
    gap (aspirine vs ACIDE ACETYLSALICYLIQUE; ibuprofene vs AINS). The
    dense recall@50 dropped to 0 with the extra catalog noise.
  - Q3 (mission): BM25 now puts a gold chunk at rank 1 (MRR = 1.0,
    nDCG = 0.390); hybrid keeps 2 of 4 gold chunks in top-10
    (R@10 = 0.50, nDCG = 0.253) versus 0.25 for BM25 and 0 for dense.
  - Q3f (focused): hybrid places a relevant chunk at rank 1 (MRR = 1.0).
  - Q5 (out of scope): all methods return random but confident-looking
    chunks (including dental anaesthetics from Pharm'Net and ANPP); an
    abstention threshold is needed.
  - Source effect: going from 8,247 to 9,546 chunks (ANPP) lowered aggregate
    recall@50 but raised BM25 MRR (0.174 -> 0.333) by moving the Q3 gold
    chunk to rank 1. Aggregate metrics are highly corpus-composition sensitive.

8. NEGATIVE RESULT
------------------
- Added French stemming (PyStemmer) to BM25. It degraded performance
  (Recall@10 0.125 -> 0.062) because "associer" and "association" collapse
  to "associ" and flood the long query. The change was reverted and
  PyStemmer removed from requirements.
